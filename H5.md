<h2>€ Schneier 2015: Applied Cryptography: Chapter 1: Foundations</h2>
Based on Bruce Schneier's Applied Cryptography (Chapter 1: Foundations), here is a summary of the key concepts and sections usually found in the foundational chapters of this classic text.

<h2>1.1 Terminology</h2> <h2></h2> <h3></h3>

 <h3>Plaintext and Ciphertext:</h3> Plaintext is the original message (M or P); ciphertext is the encrypted, unreadable version (C).
 
 <h3>Functions:</h3> Encryption (E) converts plaintext to ciphertext using a key (). Decryption (D) reverses the process ().
 
 <h3>Cryptosystem:</h3> A complete set of algorithms, keys, and protocols used to provide security.
 
 <h3>Security Objectives:</h3> Modern crypto aims for Confidentiality (secrecy), Authentication (identity verification), Integrity (no tampering), and Non-repudiation (cannot deny sending).

<h2>1.2 Steganography</h2>

 <h3>Hidden Communication:</h3> Unlike encryption, which hides the meaning of a message, steganography hides the existence of the message (e.g., invisible ink or hiding data in image pixels).
 <h3>Weakness:</h3> Once the method of hiding is discovered, the message is usually completely exposed unless it is also encrypted.

<h2>1.3 Substitution and Transposition Ciphers</h2>

 <h3>Substitution:</h3> Each element in the plaintext is replaced by another (e.g., Caesar Cipher, where letters shift positions in the alphabet).
 <h3>Transposition:</h3> The elements of the plaintext are kept the same but their order is scrambled (e.g., a "rail fence" cipher).
 <h3>Product Ciphers:</h3> Modern algorithms combine both techniques multiple times to increase security.

<h2>1.4 Simple XOR</h2>

 <h3>The XOR Operation:</h3> A fundamental building block in computer cryptography where two bits are compared ().
 <h3>Symmetry:</h3> XORing a message with a key produces ciphertext; XORing that ciphertext with the same key again perfectly restores the original message.
 <h3>Weakness:</h3> If used with a short, repeating key, it is easily broken through frequency analysis.

<h2>1.5 One-Time Pads (OTP)</h2>

 <h3>Perfect Secrecy:</h3> The only mathematically unbreakable form of encryption. It requires a key that is truly random, as long as the message, and never reused.
 <h3>Practical Issues:</h3> While perfectly secure, it is rarely used because distributing and protecting a key that is as large as the data itself is logistically difficult.

<h2>1.6 Computer Algorithms</h2>

 <h3>Restricted vs. Key-based:</h3> Restricted algorithms depend on keeping the algorithm secret (bad practice). Key-based algorithms rely on the key being secret while the algorithm is public.
 
 <h3>Symmetric Algorithms:</h3> Use the same key for both encryption and decryption (e.g., DES, AES, Blowfish). They are fast but have difficult "key distribution" problems.
 
 <h3>Asymmetric (Public-Key) Algorithms:</h3> Use a public key to encrypt and a private key to decrypt (e.g., RSA). They solve key distribution but are much slower than symmetric methods.

<h2>1.7 Cryptanalysis (Breaking the Code)</h2>

 <h3>Ciphertext-Only Attack:</h3> The attacker only has access to the encrypted messages.
 
 <h3>Known-Plaintext Attack:</h3> The attacker has access to both the ciphertext and its corresponding plaintext.
 
 <h3>Chosen-Plaintext Attack:</h3> The attacker can choose specific plaintexts to be encrypted and observe the resulting ciphertext to find patterns.
 
<h3>Rubber-Hose Cryptanalysis:</h3> A humorous but real-world term for using physical threats or coercion to get a key from a person.




<h1>Karvinen 2023: PGP - Send Encrypted and Signed Message - gpg</h1>

<h2>PGP - Send Encrypted and Signed Message - gpg</h2>

According to the article by Tero Karvinen, the following is a summary of PGP (GnuPG) usage in encrypting, signing, and verifying messages:

<h2>Core Concepts</h2>

 Encryption: Helps in ensuring that unauthorized people cannot read a message, only the person who has the matching private key can decrypt the message.
 Signing: Ensures that the message is not altered and also attests to who the sender is.
 Public/ Private Keys: You give your public key to the world to enable them to encrypt messages to you or to verify your signatures. Your personal key is a secret code to be used to unencrypt messages and to sign messages personally.

<h2>Initial Setup & Key Exchange</h2> <h3></h3>

<h3>Generate Keys:</h3> Use <i> gpg --gen-key</i> to create a new keypair (name, email, and optional passphrase). 

<h3>Exporting Public Keys:</h3> To let others communicate with you, export your key using <i>gpg --export --armor --output yourname.pub</i>.

<h3>Importing Keys:</h3> When you receive someone else's public key, add it to your keyring with <i>gpg --import theirkey.pub</i>.

<h3>Establishing Trust:</h3> After importing, you should verify the key's fingerprint (e.g., via a phone call) and then sign it using <i>gpg --sign-key [fingerprint]</i> to mark it as trusted.

<h2>Sending a Secret Message</h2>

 <h3>Encrypt and Sign:</h3> 
 To send a secure message, use the command:
 
 gpg --encrypt --recipient [email] --sign --armor --output message.pgp [file.txt]
 
 --encrypt: It uses the public key of the recipient in order to read the message.
 
 --sign: Sign with your own key to indicate that you have sent it.
 
 --armor: Transforms the output into human readable ASCII text.

<h2>Receiving and Decrypting</h2>

 Decryption: gpg -decrypt message.pgp is used by the receiver.
 Verification: In decryption, GPG will automatically verify the signature. In case it indicates Good signature, then, the message is genuine and has not been distorted.

<h2>Troubleshooting Tips</h2>

Agents: In case the key generation fails because of No such file or directory private error, restart the background agent with killall gpg-agent.
Missing Keys: When signing or encrypting, you may receive a No public key error, make sure you have properly imported and listed the fingerprints of people you are communicating with, with gpg fingerprint.
