<h1>PGP - Send Encrypted and Signed Message - gpg</h1>

According to the article by Tero Karvinen, the following is a summary of PGP (GnuPG) usage in encrypting, signing, and verifying messages:

<h2>Core Concepts</h2>

 Encryption: Helps in ensuring that unauthorized people cannot read a message, only the person who has the matching private key can decrypt the message.
 Signing: Ensures that the message is not altered and also attests to who the sender is.
 Public/ Private Keys: You give your public key to the world to enable them to encrypt messages to you or to verify your signatures. Your personal key is a secret code to be used to unencrypt messages and to sign messages personally.

<h2>Initial Setup & Key Exchange</h2> <h3></h3>

<h3>Generate Keys:</h3> Use <i> gpg --gen-key</i> to create a new keypair (name, email, and optional passphrase). 

<h3>Exporting Public Keys:</h3> To let others communicate with you, export your key using <i>gpg --export --armor --output yourname.pub</i>.

<h3>Importing Keys:</h3> When you receive someone else's public key, add it to your keyring with <i>gpg --import theirkey.pub</i>.

<h3>Establishing Trust:</h3> After importing, you should verify the key's fingerprint (e.g., via a phone call) and then sign it using <i>gpg --sign-key [fingerprint]</i> to mark it as trusted.

<h2>Sending a Secret Message</h2>

 <h3>Encrypt and Sign:</h3> 
 To send a secure message, use the command:
 
 gpg --encrypt --recipient [email] --sign --armor --output message.pgp [file.txt]
 
 --encrypt: It uses the public key of the recipient in order to read the message.
 
 --sign: Sign with your own key to indicate that you have sent it.
 
 --armor: Transforms the output into human readable ASCII text.

<h2>Receiving and Decrypting</h2>

 Decryption: gpg -decrypt message.pgp is used by the receiver.
 Verification: In decryption, GPG will automatically verify the signature. In case it indicates Good signature, then, the message is genuine and has not been distorted.

<h2>Troubleshooting Tips</h2>

Agents: In case the key generation fails because of No such file or directory private error, restart the background agent with killall gpg-agent.
Missing Keys: When signing or encrypting, you may receive a No public key error, make sure you have properly imported and listed the fingerprints of people you are communicating with, with gpg fingerprint.
